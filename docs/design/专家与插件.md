# 专家与插件的定位及关系

状态：已确认的当前设计约定。确认日期：2026-11-24。依据：项目负责人在本项目会话中对专家定义、能力绑定和职责区别的确认。

## 专家

专家是企业针对特定业务动作或业务流程抽象的执行角色。用户在会话中选择专家，由专家承接相应的业务工作与业务问题，依据业务规则推进处理并呈现进展和结果。

专家按业务类型组织，例如供应链、质量安全。质量安全下可以建立工单专家。专家的职责围绕企业业务定义，其执行需要结合任务上下文、用户权限和实际可用能力。

## 插件

本项目采用 Codex 的插件定义、打包与使用模式。插件是可安装、可分发和可版本化的能力包，可组合技能、MCP 服务配置以及相关资源或可选界面。纯技能插件也可以作为专家的能力来源。

插件的身份、内容声明和装载遵循所接入 Codex 版本支持的插件清单与配置。发现、安装、启用、更新及移除等生命周期操作通过该版本可用的接口接入。连接认证按插件所包含的服务分别处理。具体字段与接口在接入版本确定后核对。

专家可绑定多个 Codex 插件，也可单独绑定技能。解析能力时保留插件及技能来源与版本，同一技能经插件和独立绑定同时进入时去重。插件所属技能和工具仍受实际启用状态、连接及权限约束。

选择该模式的项目依据是主要采用 Codex 执行体系。这里的 Codex 指 Agent 客户端及运行时，底层具体模型由运行配置选择。

本节于 2026-11-24 参考官方插件架构及打包文档整理。版本相关格式按正式接入版本复核。

## 技能与知识库

技能提供处理方法、规范与流程，例如异常分析、信息收集和工单填写规范。专家可绑定多个技能，需要系统访问时，使用插件中提供的工具能力完成操作。

知识库提供业务依据，例如质量制度、判定标准和历史案例。专家按当前任务需要使用关联知识。

## 定位与区别

| 维度 | 专家 | 插件 |
|---|---|---|
| 核心问题 | 业务由谁承接，怎样推进到完成 | 安装后可提供哪些技能、工具及相关资源 |
| 定义依据 | 企业业务职责、动作或流程 | Codex 插件能力包 |
| 配置内容 | 职责、范围、规则、流程和验收条件 | 插件清单、技能、MCP 配置、资源和版本 |
| 使用入口 | 用户在会话中选择 | 安装并启用后，由专家或会话使用其提供的能力 |
| 复用方式 | 多次承接同类业务 | 为不同专家提供同一能力包 |
| 完成标准 | 业务目标达成或明确进入下一处理状态 | 插件正确加载，所需技能和工具可用 |

更换工单系统时，工单专家继续承担质量异常受理职责，调整插件绑定及字段映射即可。相同工单插件也可以供设备维修专家或客户投诉专家使用。

## 专家配置关系

```text
专家
├── 业务类型、职责与适用范围
├── 业务动作与流程
├── 绑定技能
├── 绑定 Codex 插件及工具使用范围
├── 关联知识库
└── 权限、审批与验收条件
```

专家绑定插件能力包，涉及工具时另行配置允许调用的操作。例如专家可查询和创建工单，关闭工单需要额外授权。用户选择专家后，实际执行范围由用户权限、专家授权和目标系统权限共同决定。

## 业务示例

以下是质量安全领域的设计示例。

用户选择工单专家，提出“这批产品出现质量异常，帮我处理”。专家收集必要信息，分析异常类型，确定处理路径，按规则请求审批，再执行建单和后续跟踪。

| 绑定对象 | 作用 |
|---|---|
| 工单插件 | 打包工单受理技能与工单系统 MCP 配置，提供查询、建单及状态更新能力 |
| 企业通讯插件 | 通知责任人员 |
| 质量异常分析技能 | 指导信息收集、分类与处理步骤 |
| 质量知识库 | 提供制度与判定依据 |

工单插件返回创建成功及工单编号后，专家依据流程判断受理是否完成，以及是否继续通知、分派和跟踪。会话呈现待补充信息、待审批、已建单等业务进展，并提供关联编号和结果。
